# Task 5C assumptions

One bullet per ambiguous call, what was chosen, and why. Closes the six
`xfail(strict=True)` tests `docs/assumptions/5B.md`/`tests/apptests/
test_report_parity.py` pinned, plus the Today/Integrity decision 5B raised
as a question rather than a gap.

## `theme_html.table()` gets `tab=`/`section=`

- **Recorded as one report note per row, not one figure per row.** A tile
  or a bar has a single number the report can show as a `Figure` (label,
  value, note); a table row does not - it is several cells, several kinds,
  with no one of them the obvious "the value". `page_shared._said()`
  already has a convention for this shape: prose, not tiles. `_record_table`
  follows it - each row becomes one `Report.note()` sentence, the row's
  cell values joined with `" · "`, under whatever `section` the caller
  named. This is additive to `theme_html.py`'s existing contract (`table()`
  already took a `write=` override the same way `tiles()`/`hbars()` did),
  not a redesign of it.
- **`"link"` and `"html"` cells are left out of the sentence.** A link
  cell's value is a bare URL - not something a reader wants mid-sentence,
  and the same information (the ticket/PR number) usually already has its
  own text column. `"html"` cells are fragments built for the page (a
  chip, an avatar, a nested `rolechip()`) - putting that markup verbatim
  into a report note would either show raw tags (if left unescaped, since
  `Report.note()` HTML-escapes what it is given) or double-escape a fragment
  that was never meant to be prose either way. Every other kind's plain
  value - not its escaped HTML rendering - is used, via a new `_plain()`
  helper: `_fmt_text()`/`_fmt_num()` already exist in this file but both
  call `_esc()`, and `Report.note()` (`report._rich()`) escapes again, so
  reusing them would double-escape every ampersand and angle bracket a real
  ticket title or PR name carries.
- **A row that reduces to nothing records nothing.** If every cell in a row
  is a link/html kind, or every remaining cell is blank, no note is
  written for that row - the same "a tile showing nothing is left out"
  rule `Report.figure()` already applies, extended to the row case rather
  than writing an empty bullet.
- **Legacy-shape rows are recorded from the same `max_rows`-truncated slice
  that gets drawn**, not the full frame - `columns.head(max_rows)`, same
  cut `_legacy_table_html` itself draws from. Recording more than the page
  shows would be a report that says more than the screen does, which is
  its own kind of parity bug.
- **`_report_for()` factors out the "get-or-create this tab's `Report`,
  costing nothing outside a live session" logic** that `_record()` already
  had inline, so `_record_table()` does not duplicate the
  `st.session_state.setdefault(...)`/`try/except` block a third time.
  `_record()`'s own behaviour (including the `Exception` message on why a
  bare script/test costs nothing) is unchanged.

## Call sites: `pages/delivery.py`, `pages/code.py`, `pages/people.py`

- **Every recordable call site in these three files got `tab=`/`section=`**,
  not only the three named by the xfail tests. The task brief's acceptance
  criterion ("every page ... contributes its tiles, bars and tables") reads
  as a page-level property, not "exactly the six pinned assertions" - so
  Code's three other `table()` calls (unprompted reviews, Devin findings
  per author, "went to draft after a review was requested") were wired too,
  even though nothing pinned them as an xfail. Recording is free when the
  call site has nothing to hide - a `tab=`/`section=` pair that never fires
  in a run with no rows is a no-op, so there is no downside to being
  thorough here.
- **Section names generally match the on-screen heading, not a fixed
  page-wide bucket** - `"Where open work sits, by team"`, `"Cycle time by
  status"`, `"Stale & abandoned"`, `"Review coverage by repo"`, `"Stuck
  queue"`, `"Devin findings per author"`, and so on, each named after the
  chart title or subheader that already introduces that content on screen.
  This was not the first attempt: `"Delivery"`/`"Code"` (matching the page's
  own `theme_html.section(...)` heading, the shape the *tiles* call sites
  already used) was tried first and reads worse in the report - every
  chart's rows landing under one generic `<h2>Delivery</h2>` with no
  indication which chart they came from, and (concretely)
  `test_delivery_hbars_are_recorded_in_the_report`'s own assertion - the
  chart's title string itself must appear in the report - fails outright
  under that scheme, since a bar's recorded entries are `(name, value)`
  pairs from the chart's rows, never the chart's own title. Per-chart
  section names fix both: the title is the section heading a reader
  actually printed reads (a real report navigation aid, not a test
  artifact), and it is exactly what the pinned test asked for. The tiles
  call sites (`section="Delivery"`/`section="Code"`) were left as they
  already were - that shape came from Agent 1B/pre-5C work, is not one of
  the six gaps this task closes, and changing it was out of scope.
- **People's two `table()` calls both use `section="People"`**, matching the
  page's own `theme_html.section("People", ...)` heading, since there is
  only one meaningful screen area here (the ranked table, plus one
  selected person's evidence list) rather than several distinct named
  charts the way Code/Delivery have.
- **The "missing report button" on People was already wired, not
  missing.** `pages/people.py` already imports and calls
  `_download_report(slot, TAB_ENGINEERING)` at every return path (from
  before this task - see `git log -- pages/people.py`). 5B's finding was
  accurate at a different level: the button call existed, but
  `_download_report` only draws the button when `not built.empty`, and
  nothing on the page ever populated `built`, so the button silently never
  rendered. Passing `tab=`/`section=` on the two `table()` calls is the
  entire fix - no second `_download_report` call site was added, because
  one was already there in the right shape.

## Today: given a report

- **Today records under `TAB_ENGINEERING`, the same shared report every
  other Engineering-tab page (Delivery, Code, People, Planning,
  Engineering) already writes into** - not a separate "Today" tab. This
  matches how the whole mechanism already works: `app.py` calls
  `_reset_reports()` once per rerun, before dispatching to whichever single
  page is on screen, so only that page's own recordings land in the
  report regardless of which literal tab name is used - `TAB_ENGINEERING`
  was already the one every sibling page uses, and inventing a second key
  for Today alone would just mean `page_shared._download_report` needing a
  new tab argument nobody else passes.
- **A report-button slot is reserved the same way `_engineering_context()`
  reserves one for every sibling page** - `st.columns([5, 1])[1]`, taken
  before the first section draws, so the button's position does not depend
  on how long the page's own reads take. Today does not call
  `_engineering_context()` itself (it calls `_engineering_data()` directly
  - no sidebar/filters to build, since the page is deliberately
  filter-free), so this one line is duplicated here rather than pulled
  through that helper, which would have meant either giving Today a
  `view`/filter object it does not use or splitting `_engineering_context()`
  into two functions - more churn than the task asked for.
- **`_status_hbars_fragment`'s `hbars(bars)` and the "This week" `tiles(...)`
  call both record under `section="Today"`** - a single section, since
  (unlike Code/Delivery) this page has one coherent "this week in numbers"
  area, not several independently-titled charts.
- **The throughput line chart (`_throughput_chart_fragment`) does not
  record.** `theme_html.linechart()` was never given a `tab=`/`section=`
  parameter by 1B (only `tiles`/`hbars`/now `table` were), and adding one
  is a bigger change than this task's six named gaps plus the Today/
  Integrity decision call for - `linechart()`'s return value is a bare SVG
  with no `(label, value, note)` or row shape to record, so it would need
  its own new recording convention, not a copy of `_record`/`_record_table`.
  Left as a real, smaller gap, noted here rather than silently expanded
  into.

## Integrity: not given a report, on purpose

- **No `_download_report` call was added, and none of `pages/integrity.py`'s
  `theme_html`/`table()` calls were given `tab=`/`section=`.** 5B raised
  this as a decision, not a gap, reading the page's own docstring ("never a
  verdict... every card carries evidence precisely so a flag is checkable")
  as an argument that the absence is deliberate. 5C's decision: keep it
  that way. The page is admin-gated specifically so an accusation-shaped
  number never leaves the screen without the innocent reading and the
  linked evidence sitting right next to it; a "Download report" file is
  exactly the mechanism that would let it leave that context - forwarded,
  screenshotted, pasted into a message with none of the surrounding
  framing. That is a different risk than Code's/Delivery's/People's numbers
  being merely inconvenient to not have on paper.
- **Documented in the code, not only in this file**, per the task brief's
  own instruction ("write one sentence in the module explaining why, so the
  next person does not 'fix' it") - `pages/integrity.py::_render_integrity_page`
  now has a comment at the `_engineering_context()` call (the `_slot` it
  hands back is unused, by design) and `_rollup_card`'s own `theme_html.
  table()` call has a one-line pointer back to it, so anyone about to add
  `tab=`/`section=` there sees the reasoning before doing it.
- **Proven, not just asserted: `test_integrity_page_is_not_in_the_report`
  runs an admin session (`BASELINE_ADMIN=1`), confirms the page actually
  drew real flag content (`"Integrity"` in the rendered markdown - the
  fixture-sanity half of the assertion), and then asserts `TAB_ENGINEERING`'s
  report contains neither `"Integrity"` nor `"tripped a flag"`.** A
  non-admin run proves nothing here (the page never gets past
  `access_gate.require_admin_password()`, so of course nothing renders or
  records - see 5B's own non-admin proof for the same gate). The admin run
  is the one that actually exercises "the page has something to hide and
  still doesn't."

## Test file

- **The six `xfail(strict=True)` markers were removed, not flipped to
  `xfail(strict=True)` with a different reason or left in place expecting
  `XPASS`.** `strict=True` already turns an unexpected pass into a failure,
  so leaving the markers on would have broken the suite the moment the
  fix landed - removing them is the only option the task's own "flip each
  xfail to a passing test" instruction leaves.
- **Two new tests for Today (`test_today_page_offers_a_download_report_button`,
  `test_today_tiles_are_recorded_in_the_report`) and one for Integrity
  (`test_integrity_page_is_not_in_the_report`) were added to the same
  file**, rather than a new file, since they extend the exact
  page-by-page parity story `test_report_parity.py` already tells and
  reuse its harness/fixtures (`_run_baseline`, `_rendered_text`,
  `_report_html`, the module-state-isolation autouse fixture) directly.
- **`test_today_tiles_are_recorded_in_the_report` checks "Open tickets" and
  "Stalled 30d+", not "Tickets resolved · 7d"/"PRs merged · 7d".** The
  credential-free baseline harness's synthetic board has no
  `resolved_count_7`/GitHub PR data to answer those two tiles' reads (both
  logged as failed credential reads), so both tiles draw with value `"—"`
  on screen - and `Report.figure()` deliberately skips any figure whose
  value is `""`/`"—"`/`None` ("a tile showing nothing is left out",
  `report.py`'s own docstring), the same rule that makes an honestly-absent
  number never masquerade as a printed zero. Asserting on those two labels
  would have pinned a flake dependent on exactly which reads that harness
  happens to stub, not a real parity property. "Open tickets" and "Stalled
  30d+" both come from the synthetic board directly (ticket counts, not an
  external read) and are near-guaranteed non-empty.
- **The module docstring at the top of the file was rewritten**, not left
  describing "partially" fixed parity and an xfail-based signalling scheme
  that no longer exists in this file - a stale docstring pointing at
  markers that were just removed would be actively misleading to the next
  reader.
