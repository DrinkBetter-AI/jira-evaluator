# Task 1A assumptions

One bullet per ambiguous call, what was chosen, and why.

- **`MAX_WIDTH`**: the mockup's `.shell{max-width:1280px}` vs. `theme.py`'s
  existing `CONTENT_MAX_WIDTH = "1560px"`. Per the task spec, the mockup wins;
  `theme.CONTENT_MAX_WIDTH` now reads `theme_tokens.MAX_WIDTH` ("1280px").

- **`ACCENTS["neutral"]`**: was the literal `#1f2937`, which appears nowhere
  in the mockup - an invented colour with no design-spec counterpart. Replaced
  it with `theme_tokens.INK["1"]` (`#111827`, the mockup's primary text ink),
  since "neutral" accent means "no status colour, plain text."

- **Greys invented in `theme.py`'s own `_STYLE` block** (`#6b7280`, `#4b5563`,
  `#9ca3af`), none of which appear in the mockup: mapped to the closest
  mockup ink rung by visual role - `#6b7280` (secondary label text) →
  `INK["3"]` (`#64748b`), `#4b5563` (body/caption text) → `INK["2"]`
  (`#475569`), `#9ca3af` (the dimmest note text) → `INK["4"]` (`#94a3b8`).
  These are the closest tokens by intended weight, not colour-distance
  matches, since the goal is one ink ladder used consistently, not a literal
  hex swap.

- **`MUTED_BG` (`#f1f5f9`)**: `theme.py`'s triage-chip background
  (`#f3f4f6`, also invented) was replaced with the mockup's own muted-chip
  background - the hex the mockup itself repeats three times for
  `.chip.gray`, `.rolechip`, and `.evrow code` - rather than left as a
  fourth invented grey. It has no `--variable` of its own in the mockup's
  `:root`, so it's exported from `theme_tokens.py` as a plain constant
  (`MUTED_BG`), not part of `PLANE` or added to `css_root()`.

- **`RADIUS` / `SPACE`**: the mockup has no `--radius-*` / `--space-*` custom
  properties in `:root` - every corner and gap is a literal on the rule that
  uses it. Rather than skip these token families, they're built from the
  values that actually recur most often in the mockup's stylesheet (counted
  with `grep -oE`), named for a later caller. They are plain Python dicts,
  not wired into `css_root()`: inventing `--variable` names the mockup itself
  never declared felt like a bigger claim than "here are the recurring
  numbers."

- **`STAGE_TONES`**: `app.py:3515` (`_STAGE_COLORS`) hand-invents nine
  distinct `(background, text)` pairs, one per Jira workflow stage, none of
  which trace to the design spec. This task does not touch `app.py`. Instead
  `theme_tokens.STAGE_TONES` maps each of the nine stage names to one of the
  four `STATUS` tones, so a later agent editing `app.py` can replace the
  invented table with `STATUS[STAGE_TONES[stage]]`. The mapping is a judgment
  call: `"info"` for ordinary in-flight stages (Backlog, To Do, In Progress,
  In Dev Env), `"warn"` for the review/staging gates (Code Review, Review in
  Staging, Review), `"crit"` for the one stage that is a stalled request for
  a human decision (Discussion Needed), `"good"` for the stage that is about
  to ship (Ready for Production).

- **`theme.CATEGORICAL` is now a `list`, not a `tuple`.** The acceptance
  criterion `theme.CATEGORICAL == theme_tokens.SERIES` cannot hold across a
  tuple/list type mismatch in Python (`(...) == [...]` is always `False`),
  and `theme_tokens.SERIES` is specified as a list. Checked every caller of
  `theme.CATEGORICAL` (`theme.py`, `app.py`, `tests/test_theme_visual.py`):
  all use indexing, `len()`, iteration, or `list(...)` - none rely on
  tuple-specific behaviour (hashing, immutability) - so this is a safe type
  change. `theme.CATEGORICAL = list(theme_tokens.SERIES)` is a copy, not an
  alias, so mutating one does not mutate the other.

- **`rank_bar`'s "Other" bar colour is now red, not grey, and was left as
  is.** `rank_bar` colours the collapsed tail with `CATEGORICAL[-1]`. Under
  the old Okabe-Ito-derived palette that was slate (`#6b7280`); under
  `theme_tokens.SERIES` it's `s8`, a red (`#e34948`), which now reads as an
  alert rather than as leftovers. Fixing this properly means changing which
  colour `rank_bar` reaches for, which breaks
  `tests/test_theme_visual.py::test_the_collapsed_tail_is_drawn_as_leftovers_rather_than_as_a_person`
  (pinned to `CATEGORICAL[-1]`) - a file this task does not own. Left the
  behaviour unchanged, corrected the now-inaccurate "drawn in the palette's
  grey" comment, and flagged it in `theme.py` and here for whoever next
  touches `rank_bar` or that test.

- **`theme_html.py`'s `_CSS` block is still missing `--s5`/`--s6`/`--s7`.**
  Out of scope - the task states `theme_html.py` belongs to agent 1B - but
  noting it here since `theme_tokens.css_root()` now emits the complete
  eight-colour set and `theme_html.py`'s own hand-rolled copy does not yet
  match it.
