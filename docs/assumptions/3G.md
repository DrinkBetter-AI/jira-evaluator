# Task 3G assumptions — legacy Engineering page repaint

One bullet per ambiguous call, what was chosen, and why.

- **The task brief's `_STAGE_COLORS` (pre-split `app.py:3524`) is not in
  `pages/engineering.py` any more — it moved to `render_shared.py` during
  the 1C split, where it already reads `theme.TYPE_META` for its pill font
  size and draws its nine (background, text) pairs from the exact hues in
  `theme.CATEGORICAL`/`theme_tokens.SERIES`, per its own comment. It is out
  of this task's file ownership (`render_shared.py` is explicitly
  off-limits), so it is left untouched here. What *is* in
  `pages/engineering.py` and *is* an invented, competing colour set is
  `_BUCKET_COLORS` — a green/amber/red map for the priority-bucket bubble
  chart (`Normal`/`High`/`Urgent`). That is the one this task fixes: it now
  reads `theme.ACCENTS["good"/"warning"/"danger"]`, the same three tones the
  KPI tiles already use for "fine" / "needs attention" / "needs attention
  now", rather than a bespoke hex triad. Not `theme_tokens.STAGE_TONES` —
  that table maps Jira *workflow status* strings, not priority buckets, and
  extending it to a second, unrelated axis would be a bigger claim than this
  task makes.

- **The bubble chart's dynamic-color branch (`color_by` a free column —
  priority, status, assignee, ...) now passes
  `color_discrete_sequence=theme_tokens.colorway()` to `px.scatter`.** It had
  no explicit colour source before and fell through to Plotly's own default
  qualitative sequence, which is a sixth palette this dashboard used to have
  and the acceptance criterion ("plotly colorway from theme_tokens.colorway()")
  rules out. The aggregated-priority branch already had its own deliberate
  `color_discrete_map=_BUCKET_COLORS` and keeps it — a bucket's colour
  carries meaning (danger = urgent), and `apply_palette`/`colorway()`-style
  first-free-colour assignment would throw that meaning away, exactly as
  `theme.apply_palette`'s own docstring warns against.

- **Banner: `theme_html.callout()` for the framing sentence, a hand-built
  themed link row underneath for the five links — not `callout()` alone.**
  `callout()` HTML-escapes both `title` and `body`, so real `<a>` tags
  cannot live inside it. It is still the right tool for the framing text (a
  themed card, tokens plugged in through `.vv`'s CSS scope), so it renders
  the "why this page still exists" sentence; a second fragment underneath,
  sharing the same `.vv` scope and the same `--t-body` type-scale variable,
  is the actual list of links. Both fragments go through one
  `theme_html.render()` call so the `.vv` scope opens once.

- **`theme_html.css()` is called once, from inside `_render_legacy_banner()`,
  because this page otherwise never uses `theme_html.py` at all.**
  `pages/engineering.py` draws its chrome through `theme.py`
  (`_kpis`/`_tile` from `page_shared.py`, `theme.rank_bar`, `theme.plot`),
  not through `theme_html.py`'s mockup-shaped component library the way
  `pages/code.py` and `pages/delivery.py` do. `callout()`'s CSS variables
  (`--info`, `--t-meta`, `--t-body`, ...) only exist once `theme_html.css()`
  has run, scoped under `.vv`; calling it once, right where the one
  `theme_html` component on this page is built, is cheaper than making the
  rest of the page's styling machinery depend on it.

- **Link targets are root-relative paths (`/`, `/people`, `/delivery`,
  `/code`, `/planning`), read from `render_shared`'s own
  `TODAY_PAGE_TITLE`/`PEOPLE_PAGE_TITLE`/... constants and `app.py`'s
  `_page_specs()` `url_path` values, not `st.page_link`.** `st.page_link`
  needs the exact `st.Page` object (or a file path Streamlit's file-based
  router recognises); the five pages here are registered as function-backed
  `st.Page`s built inside `app.py`'s `_pages()`, a module this task does not
  own and that would have to be imported into `pages/engineering.py` to hand
  those objects back — a heavier, more fragile dependency than five plain
  anchor tags to the real, already-live routes those pages are served at.
  A plain `<a href="/people">` is a full browser navigation rather than an
  in-app rerun, which is the honest cost of not touching `app.py`.

- **The banner sits above everything, including the existing
  `st.caption("Visual monitoring for stale, idle, and high-risk tickets.")`
  and the Individual-scope early return (`_render_individual_page`).** It is
  the first thing a reader who followed an old bookmark should see, before
  the page decides which of its two shapes (org-wide sections, or one
  engineer's Individual page) to draw — a reader narrowed to a single name
  is exactly as likely to have arrived via an old link as one looking at the
  full page, so the banner is unconditional rather than carved out for one
  scope.

- **No change to `docs/assumptions/1A.md`'s or `1C.md`'s prior calls.**
  Nothing here revisits `theme_tokens.MAX_WIDTH`, the type ladder, or the
  `render_shared.py` API frozen by those tasks; this page already imported
  `theme` and drew its type/colour through it before this task, and
  continues to.
