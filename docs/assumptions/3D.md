# Task 3D assumptions

One bullet per ambiguous call, what was chosen, and why. All changes are
additive to `pages/code.py`; the nine sections that already matched the
mockup are untouched except where noted.

## Bypassing `data_layer.py` for the two new GitHub reads

- `data_layer.py` (out of ownership) has no cached wrapper for
  `github_client.fetch_open_prs_extended`/`fetch_merged_prs_extended` yet —
  2D's own "Render call sites for Phase 3" note says so explicitly and lists
  adding one as the next agent's job, not this task's. Rather than wait or
  reach into an unowned file, `pages/code.py` calls `github_client` directly:
  `github_client.load_github_env()` for the token/org, then
  `fetch_open_prs_extended`/`fetch_merged_prs_extended` for the extended pool.
  Wrapped in a page-private `st.cache_data(ttl=300)` (`_extended_pr_pool_cached`)
  matching the 5-minute TTL `data_layer.py` already uses for the plain reads —
  `github_client` itself floor-caches the real GraphQL call at >=1h
  internally (per 2D's assumptions doc), so this 5-minute layer only saves
  the Python-side concat on repeat reruns within a session, not a second
  network round trip.
- The same pattern, and the same reasoning, for the new
  `_open_pr_total_including_drafts_cached`: a direct `github_client._search_count`
  call (via the private `_without_excluded` helper, reused rather than
  reimplemented, so the exclusion list is guaranteed identical to every other
  count on this page) with its own 5-minute cache. No `>=1h` floor exists for
  this one inside `github_client.py` — it is a single `issueCount` GraphQL
  read (1 point), cheap enough that a page-level 5-minute cache is enough on
  its own.
- Both cached wrappers are thin: an outer, uncached function
  (`_open_pr_total_including_drafts`, `_extended_pr_pool`) checks for a
  missing token/org first and returns the honest "nothing to ask" value
  without ever touching the cache. Tests call only the outer, no-token path —
  the cached, real-fetch path is already covered by `test_pr_quality.py`'s
  extended-fetch/degrade tests at the `github_client` level (2D, 20 new
  tests), so this task's tests do not re-mock GitHub network calls, matching
  every other test in this file (none of them touch the network either).

## Reading private `github_client`/`roles` functions from a different module

- `_without_excluded` and `_search_count` are module-private (leading
  underscore) in `github_client.py`, which this task cannot edit. Calling
  them from `pages/code.py` rather than duplicating the exclusion-list
  construction is the smaller risk: a second, hand-written copy of "which
  repos are excluded" could drift from the real one and make the "of N
  including drafts" total describe a different population than the "Open
  PRs" tile next to it. Flagged here since it is private-API reach-across,
  not a normal import.
- `roles.load_roster()` (public) plus its `name_for_login`/`role_of` are used
  to resolve a PR author's GitHub login to a Jira name to a role. Both are
  public API on `roles.py`, no private reach needed there.

## Where "unprompted reviews" lives: its own `st.columns` slot, not a table column

- "Give it its own column" is read literally as a Streamlit UI column —
  the existing Devin-findings / Review-citizenship section already used
  `left, right = st.columns(2)`; this becomes `left, mid, right =
  st.columns(3)` with the new section in `right`. The alternative reading
  (a new column *inside* the citizenship table) was rejected: unprompted
  reviews needs its own evidence links and its own empty state
  ("needs the extended PR payload"), which citizenship's plain
  `st.dataframe` has no way to draw (no HTML in `st.column_config`), and
  folding two different degradation stories into one table row would hide
  which one is actually missing.

## PR-evidence links join by number only, first match wins

- `pr_quality.unprompted_reviews` hands back PR numbers as evidence, not
  URLs — it has no reason to carry one, and this task cannot add one to a
  compute module it doesn't own. `_pr_url_lookup` rebuilds the join from the
  same pool the numbers came from (`number` → `url`), keeping the first URL
  seen per number. A PR number can repeat across repos; a reader should take
  a linked number as "here is *a* matching PR", not proof there is only one.
  A number with no URL in the pool (should not happen in practice, since the
  numbers come from the same frame) falls back to a bare `#N`, never a
  broken link.

## Devin-findings table switched from `st.dataframe` to `theme_html.table`

- Only this one sub-table changed rendering technique, and only because the
  exempt chip needs it: `theme_html.rolechip()` returns a real HTML
  fragment, and `st.column_config` has no way to draw arbitrary markup in a
  cell. `Column(kind="html")` is exactly the case `Cell`'s own docstring
  describes as safe: a fragment this file itself built
  (`theme_html.rolechip(...)`), never raw Jira/GitHub text. Review
  citizenship (the other half of that row) is left as `st.dataframe` —
  nothing in this task's scope touches it.
- "exempt" is read straight off `roles.EXEC_ROLE` via `roles.load_roster()`,
  the same role `roles.rubric_for_role` already refuses to score
  (`RubricLookup(status="exec", ...)`). No new exemption list was invented;
  this is the one the roster already carries.

## Draft-hiding row: plain function, not `@st.fragment`

- Every other new/touched section that draws inside
  `_render_findings_and_citizenship` stayed inside that function's existing
  `@st.fragment` wrapper. `_render_draft_hiding_row` is its own, new,
  top-level section and was deliberately left as a plain function rather
  than fragment-wrapped: a fragment-decorated function called outside a real
  Streamlit script run (bare mode — how every existing test in this file
  calls page-private functions directly) silently returns `None` without
  running its body at all, which would have made the empty-state and
  flagged-row behavior untestable without a full `AppTest`. None of this
  page's *existing* tests use `AppTest`, and this task's tests follow that
  precedent rather than introducing a second testing style for one section.

## The "renders end to end with no GitHub data" test

- Verified two ways. (1) A real `streamlit.testing.v1.AppTest` run against
  the synthetic 1000-ticket board with no GitHub token (same harness shape as
  `tests/apptests/baseline_apptest.py`, run manually during this task, not
  committed as a new file — this task owns `tests/test_code_page.py`, not
  the `tests/apptests/` directory) confirmed the Code page renders with zero
  exceptions end to end. (2) `tests/test_code_page.py` itself has a bare-mode
  test (`test_the_page_renders_end_to_end_...`) that calls
  `_render_code_page()` directly with a stubbed `_engineering_context`
  (`github_ready=True`, every PR frame empty) and asserts no exception plus
  the degraded-callout text — the `@st.fragment`-wrapped sections
  (repo coverage, stuck queue, findings/citizenship — all pre-existing, none
  touched) silently no-op in bare mode rather than raising, so this
  specifically exercises the plain-function path: the KPI tiles, the
  including-drafts lookup, the extended-pool honest degradation, and the
  draft-hiding row's empty state.
- **`tests/apptests/baseline_apptest.py` was not re-run as part of "keep the
  suite green" for this task's own regression check**, because it currently
  fails on the *`today`* page (`NameError: name
  '_hero_and_decide_fragment' is not defined`, `pages/today.py:988`) — a
  concurrent, unrelated edit to `pages/today.py` by another agent (that file
  is `M`odified in `git status` and this task never touched it). That script
  runs all six engineering pages in one process before `code` ever gets a
  turn, so today's break blocks the whole file regardless of the Code page's
  own correctness. Confirmed independently, outside that shared script, per
  the point above: the Code page itself renders clean.
